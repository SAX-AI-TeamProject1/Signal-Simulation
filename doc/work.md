# 작업 기록

## 2026-08-06 — 웹캠 화질 이상 → EMERGENCY

### 요구사항
웹캠 렌즈 상태에 따른 비상 처리. 대상: **해상도 저하 / 화면 끊김·정지 / 빛반사 / 블러 /
부분 가림 / 저조도**. 단, **적당한 저하인데 수신호 인식은 잘 되는 경우는 비상이 아니다.**
그리고 **기동 순간부터 화질이 나빠도 잡혀야 한다.**

### 판정 구조

```
비상 = 화면 정지·끊김                        (인식 여부와 무관)
     또는 절대 축 이상                        (기준치 불필요 — 보정 전에도 판정)
     또는 상대 축 이상                        (기준치 대비)
     또는 (가려짐  그리고  관절이 안 잡힘)      ← 마지막 안전망
```

**절대 축**(프레임 한 장으로 판정, 보정 전에도 돔)

| 판정 | 기준 |
|---|---|
| 저조도 | 상위 5% 밝기 < 60 |
| 빛반사 | 포화(≥250) 화소 > 15% |
| 화면 뭉개짐 | 구조(1/4 축소 후 라플라시안 분산) < 30 |
| 해상도 변경 | 프레임 크기가 바뀜 |

**상대 축**(기동 시 기준치 대비)

| 판정 | 기준 |
|---|---|
| 흐림·해상도 저하 | 선명도 < 22% |
| 가려짐 | 구조 < 35% |
| 노이즈 | 구조/선명도 비 < 25% |
| 부분 가림 | 죽은 타일 ≥ 35% (4x4 격자, 타일별 기준치의 20% 미만이면 죽음) |

### 지표를 고르며 탈락시킨 것들 (전부 실측 근거)

같은 웹캠에서 받은 **원본 640x480 프레임 두 장**으로 판별력을 비교했다. HUD 스크린샷으로
맞추다 계속 어긋났는데, 창이 프레임을 세로로 눌러 그려서 스크린샷에는 없던 흐림이
더해지기 때문이었다 — 같은 순간에 노드는 0.41, 스크린샷 측정은 0.619 였다.

| 지표 | 뿌연 화면(비상이어야) | 정상 화면(통과해야) | 판정 |
|---|---|---|---|
| **구조** | **8.5** | **106.4** | 채택 — 12.5배, 노이즈에도 순위 유지 |
| 선명도 | 8.8 | 27.9 | 상대 축으로만 |
| 잡음비 | 0.97 | 3.82 | 탈락 — 정상에 노이즈 σ=2 얹으면 1.02 로 겹침 |
| Crete 무참조 블러 | 0.422 | 0.510 | **탈락 — 역전.** 노이즈를 디테일로 읽음 |
| 대비 / 밝기 p95 | 25.7 / 97 | 25.0 / 101 | 탈락 — 차이 없음 |

그 밖에 폐기한 축:
- **기울어짐(에지 방향 히스토그램).** ±45도까지 5도 오차로 추정되고 장면 변화에도 0도로
  안정적이었지만, 90도 주기로 접는 탓에 정확히 90/180도 전복은 못 잡고, 심한 블러에서
  -20도 같은 헛값이 나왔다. 사용자 판단으로 제거.
- **라플라시안 분산 단독.** 렌즈가 아니라 장면을 잰다 — 깨끗한 화면끼리도 233~1282 로
  5.5배 흔들렸다. 게다가 실제 저조도에서는 웹캠이 게인을 올려 노이즈가 폭증하는 바람에
  **거꾸로 올라간다**(선명도 2457%). 그래서 상대 축으로만 쓰고 절대 판정에는 안 쓴다.

### 기준치 오염 방지
이 판정기의 유일한 침묵 경로는 "기준치가 나쁜 화면에서 잡히는 것"이다. 세 겹으로 막았다:
1. **예열 20프레임을 버린다** — UVC 웹캠은 열린 뒤 1~3초간 노출·초점을 맞춘다.
2. **표본의 상위 75 백분위**를 기준치로 (중앙값은 흐린 프레임에 그대로 깎인다).
3. **절대 축이 이상이면 표본 자체를 안 받는다** — 나쁜 채로 시작하면 보정이 진행되지 않고
   그동안 계속 비상으로 보고하다가, 화면이 정상으로 돌아와야 표본이 모인다.
그래도 의심스러우면 로그로 경고한다(기준치의 150% 가 30프레임 지속될 때).

### 비상 판정 지연
- 저조도·빛반사·뭉개짐: **3프레임(약 0.24초)** — 보정 전에도 절대 축이 돌기 때문.
- 지표는 비대칭 EMA로 평활한다 — 나빠지는 방향 0.6, 좋아지는 방향 0.2.
  복구를 느리게 두는 건 의도다(한두 프레임 돌아온 것으로 비상이 풀리면 더 위험).
- 게이트 경로는 `NO_POSE_FRAMES=6`(약 0.5초)을 창 비율과 OR 로 묶어 앞당겼다.

### 함께 정리한 것
- `"인식 불가"` → **`"인식 대기중"`**(`ui.NO_SIGNAL_TEXT`). 확정된 라벨이 `idle`인 경우도
  대기로 본다 — 로봇 입장에서 "확정 신호 없음"과 "idle 확정"은 같은 일인데 화면만
  초록 "확정: idle"로 달랐다.
- 상태 3종(비상/확정/대기)의 문구·색 규칙을 `ui.header_for()` 한 곳으로.
- **렌즈 측정이 `draw_detections` 뒤에 있던 순서 버그 수정.** 스켈레톤 선이 인공적인
  고대비 엣지라 선명도를 부풀리고(실측 평균 +157%), 하필 사람이 잡히는 동안에만
  그렇게 된다 — 신호수가 화면에 있는 내내 판정이 무뎌졌다.
- `is_blurred` → `lens_fault` 개명.
- `scripts/capture_lens_sample.py` — 웹캠 원본 프레임을 저장하고 지표를 찍는 계측 도구.
  임계값 조정은 반드시 이걸로 받은 원본 기준으로 할 것(스크린샷 금지).

### 남은 과제
- **빛반사 판정선(포화 15%)이 이 카메라엔 느슨할 수 있다.** 원본이 어두운 편(p95=101)이라
  +150 을 더해도 포화가 3.7% 에 그쳐 안 걸리고 +180(35.6%)부터 걸린다. 실제 조명 반사가
  어느 정도인지 `capture_lens_sample.py` 로 재서 맞출 것.
- **화면은 멀쩡한데 카메라가 엉뚱한 곳을 보는 경우**(천장을 향해 넘어짐 등)는 영상
  통계만으로 "아무도 없다"와 구분할 수 없다. 등급을 나누는 것이 답으로 보인다 —
  수신호 게이트가 열려 있는데 N초 넘게 사람이 안 잡히면 **정비 알림**(비상정지 아님).
  팀 결정 필요.
- **벤더 사본 갱신 절차.** 화질·상태 판정 코드의 원본은 상류 Signal-Vision 이다.
  `setup_infer_env.py` 는 GitHub 의 **최신 태그**를 clone 하므로, 상류에 커밋·푸시한 뒤
  **새 태그**를 올려야 재벤더링에 반영된다.

## 2026-08-05 — 시뮬레이터 EMERGENCY(렌즈 블러) 미표시 수정

### 배경
Signal-Vision에는 렌즈 블러를 판정해 EMERGENCY UI를 띄우는 기능이 있으나,
그 코드를 벤더링해 쓰는 Signal-Simulation의 camera_node 경로에서는 EMERGENCY가
전혀 뜨지 않았다.

### 원인
- `camera_node/inference.py`가 `LensHealthMonitor`(블러 판정기)를 아예 만들지 않고,
  `SignalStabilizer`에 `is_blurred=False`를 하드코딩해 넘기고 있었다.
- 독립 실행 경로(`vision_hand/inference/function.py`)에는 있던 블러 배선이
  camera_node로 옮겨질 때 누락된 것.

### 변경 내용

1. **camera_node에 블러 판정 배선 추가** — `camera_node/inference.py`
   - `LensHealthMonitor` import 및 인스턴스 생성(추론 워커 전용).
   - `_infer_impl`에서 매 프레임 `is_blurred = self._lens_monitor.update(frame)`를
     계산해 `mark_person_absent`/`stabilizer.update`에 전달(하드코딩 `False` 제거).
   - 블러 판정은 윈도우 충족 여부와 무관하게 매 프레임 실행 — 초기
     `BLUR_CALIBRATION_FRAMES` 동안 정상 기준치를 잡아야 하기 때문.

2. **EMERGENCY 트리거 정책 변경** — `vision_hand/inference/predict.py`
   - 기존: "렌즈 블러 AND 인식 저하"가 겹치고, 이미 확정된 신호가 있어야만 EMERGENCY.
     → 실제로는 카메라를 완전히 상실했을 때만 떴다.
   - 변경: **렌즈 블러 단독으로 EMERGENCY + 즉시정지**. 확정 신호 유무·사람 유무와
     무관하게, `is_blurred`가 True면 최우선으로 즉시정지 처리하고 나머지 안정화
     로직은 건너뛴다. 화면이 다시 선명해지면 자동 해제.
   - 관절만 못 잡는 경우(이미지 선명)는 정상 운용으로 두어 오탐을 막는다.
   - `_reset_to_unknown`에서 emergency 관리를 분리 — emergency는 오직 `is_blurred`로만
     결정하도록 호출부에서 세팅.

3. **setup_perception_env.py — python-dotenv 설치 직후 import 실패 수정**
   - `--user` 설치 직후, 인터프리터 시작 시점에 user site-packages 경로가
     `sys.path`에 없어 같은 프로세스에서 `import dotenv`가 실패하던 문제.
   - 설치 후 `site.addsitedir()` + `importlib.invalidate_caches()`로 경로를 반영해
     재실행 없이 한 번에 통과하도록 수정.

### 반영 방법
Python 소스만 변경했고 `--symlink-install`이므로 재빌드 없이 노드 재시작만으로 반영된다.

### 남은 튜닝 포인트 (`vision_hand/capture/extractor.py`)
- `BLUR_CALIBRATION_FRAMES = 30`: 시작 시 화면이 선명해야 정상 기준치가 잡힌다.
- `BLUR_RATIO_DROP = 0.5`: 선명도가 기준치 절반 밑으로 떨어져야 블러로 판정.
  약한 초점흐림까지 잡으려면 `0.6~0.7`로 올려 감도를 높일 수 있다.
